# RevoHelper V1.0.3

本次包含 V1.0.3 的累计更新，主要改善性能模式切换、频率限制恢复、开机自启、硬件信息读取及水冷连接判定。

## 性能模式与频率控制

- 修正点击狂暴主卡后，若后续 Boost 或频率设置失败，可能残留办公模式频率上限并错误提示「已恢复」的问题。现在会保留实际档位，按实际档位同步频率，并如实反馈未完成的部分。
- 修正切换失败回滚时可能擅自开启静音策略的问题；只有原本开启的子策略才会被恢复。
- 修正部分设备基础档位切换成功后，上一档位的频率上限没有解除的问题；目标档位没有保存频率设置且上一档位没有 RevoHelper 上限时，不改动现有 Windows 设置。
- 档位切换较慢时多观察几秒再判定失败，减少把较慢生效的切换误判为失败的情况，并记录观察期间的生效耗时，便于继续定位切档故障。
- 将基础狂暴模式与可选的静音、高能策略分开。点击狂暴主卡时，不再因为附加策略未能应用而阻挡基础狂暴档位。
- 手动选择静音或高能策略失败时，若实际仍处于狂暴模式，则保留基础狂暴档位并反馈附加策略未确认；同时按实际档位同步频率设置，避免忽略办公模式遗留的上限，同步失败会单独反馈。
- 修正部分设备因性能档位支持信息缺失或不完整，导致基础模式按钮变灰、无法点击的问题。已有基础模式允许手动尝试，以实际响应确认切换结果。
- 改进当前档位无法识别或支持信息缺失时的基础切换流程，避免被附加功耗、睿频或频率设置的读取阻挡。
- 支持再次点击已选中的档位进行重试；连续切换时，较新的选择可替代尚未发送的旧请求。
- 改进上次限充会话的恢复处理：平台与实时充电阈值确认恢复后，不再仅因缓存差异误拦截性能切换。
- 新增损坏频率恢复记录的主动解除路径：在「性能调整」中手动关闭「Windows 通用最高处理器频率」开关时，可保留损坏记录副本并解除当前电源方案的残留上限，避免持续限频且无法调整。
- 加强频率恢复记录的保存与校验；解除过程中发生中断或部分失败时保留恢复信息，避免把残留上限再次作为正常原值恢复。

## 显卡输出

- 修正支持信息缺失被当作「不支持」的问题：以 GCU 的实时结果为准；GCU 未说明且注册表缺少信息时，允许手动尝试并以回读确认结果；只有明确不支持时才拒绝。

## 开机自启

- 改进开机自启变更失败时的恢复，保留变更前完整的任务、程序路径及相关启动状态，避免只恢复界面开关、实际设置却不一致。
- 部分清理、状态确认或设置保存失败时，尝试恢复原状态并重新读取实际结果；恢复不完整时保留具体原因，避免错误显示成功。

## 硬件信息与水冷

- 补充 AMD CPU 温度、封装功耗及核心频率的传感器名称识别，尝试改善名称不匹配导致的 `N/A`；仍待 AMD 设备实测。
- 修正水冷控制信息缺失时被误判为不可控制的问题；允许手动尝试连接或断开实际发现的设备，并确认实际连接结果。

## 服务状态与反馈

- 修正设置中 Intel 平台服务的操作反馈：停止或恢复服务后，等待实际状态确认，避免命令已发送就提前显示成功。
- 正确显示服务正在启动、正在停止等过渡状态；操作部分失败或状态读取失败时，保留真实反馈并刷新可读取的状态。
- 补充性能切换、频率应用、回滚及服务操作的本地诊断，便于定位切换失败原因。

## 当前已知情况

- 仍有部分性能模式切换失败的问题在调查中，包括开机后需手动重启 Intel 平台服务才能恢复的反馈；本次不代表所有切换故障都已解决。
- 当前没有 2023 极光实机，对该机型的改善仍待用户实际确认。
- AMD CPU 读取改动仍待 AMD 设备实测；Radeon 610M 核显读数全部为 `N/A` 的问题尚未解决。
