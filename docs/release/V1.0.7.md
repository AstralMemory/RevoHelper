本次 V1.0.7 相较 V1.0.6，新增诊断报告，重新整理了设置页和主页读数的检测方式（CPU 和显卡读不到时都有备用来源），修复充电上限偶尔被意外停止的隐患，界面文字更清晰，并处理了几条用户反馈。

### 新增：

## 诊断报告

- 设置页“故障排查”里新增“诊断报告”，用于向开发者反馈问题。
- 分两种：
  - 简短报告：不超过 500 字，可以直接发 B 站私信或评论。包括机型和 BIOS、EC 版本，处理器和显卡，当前模式，充电上限，官方控制台服务是否正常，哪些功能没有确认可用，主页读数，以及最近 24 小时记录到的失败。
  - 完整报告：在简短报告的基础上，加上显卡功耗读数、充电上限的运行记录和最近 24 小时的运行日志，大约需要 10 秒，适合保存为文件后发送。
- 生成后先在下方显示全文，不会自动复制，也不会覆盖你剪贴板里原有的内容。看过内容后，再自己点“复制”或“保存为文件”。
- 只读取，不修改任何设置。报告里不含用户名、电脑名、序列号、文件夹路径和网络地址；运行日志里出现的这类内容会被替换掉。

### 优化与修复：

## 设置

- 设置页从 7 组合并为 3 组，内容不变：
  - 常规：随 Windows 启动、自动检查更新。
  - 界面与窗口：语言、外观、窗口缩放、窗口始终置顶、记住窗口位置。
  - 故障排查：设备与功能状态、诊断报告、可能冲突的服务。
- 修正先打开 RevoHelper、后打开官方控制台时，设置页一直显示官方控制台“未运行”的问题。现在每次打开设置页都会重新检测。

## 读数检测

- 重新整理了主页读数的来源。传感器读不到、显示 N/A 的项，改用 Windows 自带的数据补上，不再针对个别机型单独处理。传感器已经读到的值不会被替换；在传感器读数完整的电脑上，备用来源不会运行。
- CPU 的备用来源：
  - CPU 占用和实时频率：来自 Windows 性能计数器，与任务管理器一致。
  - CPU 功耗：来自处理器自带的能耗计数器，由 Windows 直接提供，没有安装 PawnIO 驱动也能显示。
  - Intel 核显功耗：来自同一个能耗计数器里的核显部分。
  - CPU 温度：依次取传感器、官方控制台服务、主板固件报告的温度（ACPI 温区）中第一个可用的。
- 显卡的备用来源，与任务管理器“性能”页里的显卡数据同源：
  - 显卡占用：Windows 统计的各个显卡引擎的占用，取最忙的一个，与任务管理器一致。
  - 独显温度、显卡频率和显存容量：由显卡驱动通过 Windows 报告。
  - 传感器完全识别不到的显卡，也会显示上面这些读数。显卡功耗没有通用的来源，这种情况下仍显示 N/A。
  - 读取不会唤醒休眠的独显：只在 Windows 报告独显已通电时才询问驱动，独显闲置时还会暂停询问一段时间，让它能正常进入休眠。
- 传感器组件整体出错时，CPU 和显卡仍会显示 Windows 提供的读数，不再全部变成 N/A；某个设备单独出错时，只影响它自己那一行。
- 新机型、新驱动的传感器名称和以前不同时，也能按类别找到对应的读数。
- 核显和独显改为按硬件信息区分（PCI 厂商号；Intel 核显固定在 PCI 总线 0 的 2 号设备），不再看显卡名字，以后新显卡改名也不会认错。
- 显卡在传感器里的名字与 Windows 里的不一致时，按厂商找到主页上对应的那一行。
- 独显休眠时，温度和频率显示“休眠”，不再显示 N/A。传感器读不到的独显，也按 Windows 报告的电源状态显示“休眠”。
- WMI 无法使用的电脑，机型、BIOS 和处理器名称改从注册表读取，显卡列表改从设备管理器读取。
- 外置监控条在只有一块无法分类的显卡时，也会显示它的读数。

## 充电上限

- 修正限充运行中偶尔记录“拒绝访问”的问题。限充会定期写一个状态文件，窗口同时在读它；两边偶尔撞上时，写入失败被误当成与固件通信失败，连续几次就可能停掉限充，并且每次都留下一个临时文件。现在写入会短暂重试，失败也不影响限充，并会清理以前留下的临时文件。

## 界面

- 修正界面文字发粗、发虚的问题。界面文字改用 Windows 的 ClearType 渲染，主页、设置页和各个抽屉里的文字都更清晰，字重不变；窗口阴影的绘制方式也随之调整，外观基本不变。
- 英文界面主页的“Performance”按钮文字太长，贴到了按钮边缘，改为“Tuning”。
